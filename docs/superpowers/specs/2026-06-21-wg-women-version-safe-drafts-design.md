# Version-safe review drafts for `wg-women.html`

תאריך: 2026-06-21
סטטוס: מאושר לתכנון

## הבעיה

`wg-women.html` נשלח ללקוח כקובץ HTML עצמאי לסבב הערות. הקובץ שומר עריכות/הערות ב-`localStorage` תחת מפתח קבוע (`wg_women_final_v2`) ומשחזר אותן אוטומטית בטעינה (`loadAll`).

`localStorage` משויך ל-origin (לא לקובץ), והשחזור מתבצע לפי מזהים מיקומיים (`eid` / `cid` = `c0,c1,...`). כשנשלחת **גרסה חדשה** של הקובץ עם מבנה/תוכן שונה, ה-overlay השמור מגרסה ישנה נצבע על אלמנטים שמשמעותם השתנתה — והלקוח ראה **נתונים/גרפים שונים לגמרי** מקובץ הבסיס. תקלה שאירעה אצל לקוח בפועל.

שורש הבעיה: שחזור state שמור על DOM שעלול להיות שונה, עם מפתח משותף לכל הגרסאות באותו origin.

## המטרה

לשמר רשת ביטחון של autosave (עריכות שורדות סגירת טאב בטעות), אך להפוך דליפה בין-גרסאות לבלתי אפשרית מבנית, ולהפוך את המצב לגלוי במקום נסתר.

החלטה: רשת ביטחון "אבל בבטחה" — autosave משויך לקובץ הספציפי הזה, שחזור רק בהתאמה.

## הגישה (Approach B — Automatic content fingerprint)

טביעת אצבע אוטומטית מהתוכן, ללא תלות במשמעת ידנית של בנייה/גרסאות.

### 1. Fingerprint (זהות הגרסה)
בטעינה, לפני החלת כל שינוי, מחשבים hash מהמבנה הניתן-לעריכה ה**מקורי** של הקובץ:
רשימה מסודרת של מזהה כל אלמנט (`eid`/`cid`) + ה-`innerHTML` המקורי שלו (נקרא מ-`dataset.original`, שמוגדר ישירות מה-HTML המילולי של הקובץ).
hash מחרוזת קצר (djb2/FNV) → hex קצר.
אותו קובץ ⇒ אותה טביעת אצבע; כל בנייה שמשנה תוכן/מבנה ⇒ טביעת אצבע שונה.

### 2. מפתח אחסון
`wg_women_draft_<fingerprint>` במקום `wg_women_final_v2` הקבוע.
טיוטה קשורה פיזית לגרסת קובץ אחת; טיוטה מגרסה אחרת פשוט לא תימצא → **דליפה בלתי אפשרית מבנית**.

### 3. לוגיקת טעינה
חישוב fingerprint → חיפוש `wg_women_draft_<fp>`.
- נמצא: שחזור עריכות/הערות לפי id (מבנה זהה מובטח) **+ הצגת באנר שחזור**.
- לא נמצא: הצגת תוכן הקובץ הטהור.
לעולם אין צביעה שקטה בין-גרסאות.

### 4. לוגיקת שמירה
Autosave (ב-`input`) כותב למפתח מבוסס-fingerprint.
בשמירה **גוזמים** (prune) מפתחות `wg_women_draft_*` אחרים + את המפתח הישן `wg_women_final_v2`, כדי שטיוטות ישנות לא יצטברו בדפדפן הלקוח.

### 5. ממשק אמון (החלק האינטואיטיבי)
- **באנר שחזור** (רק כשטיוטה שוחזרה): "מוצגות הערות שטרם נשמרו לקובץ — [נקה והצג מקור]". הכפתור מנקה את טיוטת הגרסה הזו + טוען מחדש.
- **תווית סטטוס** בסרגל התחתון: "מקור" (אין שינויים שלא נשמרו) ↔ "שינויים שלא נשמרו" (טיוטה פעילה), מתחלפת חי תוך כדי עריכה.
- הכפתורים הקיימים **"איפוס הכל"** ו**"שמירת הקובץ לשליחה"** נשארים; "איפוס הכל" מנקה כעת את מפתח ה-fingerprint.

### 6. ייצוא — ללא שינוי
`exportHTML()` ממשיך לסריאל את ה-DOM החי עם העריכות צרובות פנימה. הקובץ המיוצא נושא את העריכות ב-HTML המילולי שלו, כך שה-fingerprint שלו ממילא שונה מזה של הטיוטה — נכון, כי התוכן כבר בקובץ.

## טווח (Scope)
שינוי עצמאי יחיד לבלוק הסקריפט בתחתית `wg-women.html` (אזור `localStorage`/toolbar, ~שורות 1294–1518) + אלמנט באנר קטן + מעט CSS.
לא נוגעים בנתונים, בגרפים או במבנה.

## מקרה קצה (מצוין במפורש)
אם ללקוח יש עריכות שלא נשמרו בדפדפן A ושולחים שוב את **אותו** קובץ — העריכות משוחזרות (אותו fingerprint). זו ההתנהגות הרצויה (רשת ביטחון). הדליפה שמבטלים היא בין גרסאות **שונות**, ש-fingerprinting מחסל.

## אימות (כיצד נדע שעובד)
1. גרסה ישנה עם טיוטה שמורה → טעינת גרסה חדשה (תוכן שונה) → מוצג תוכן הבסיס, ללא דליפה, ללא באנר.
2. עריכה → reload של אותו קובץ → עריכות משוחזרות + באנר מוצג.
3. "נקה והצג מקור" / "איפוס הכל" → טיוטה נמחקת, מוצג מקור.
4. עריכה → ייצוא → פתיחת הקובץ המיוצא → תוכן צרוב מוצג, ללא באנר זר.
5. תווית הסטטוס מתחלפת נכון בין "מקור" ל"שינויים שלא נשמרו".
