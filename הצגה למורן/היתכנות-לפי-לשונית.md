## 0. What changed in this STT revision

The Gold layer went from **2 facts + 5 dims** to **7 facts + 5 dims**, and a Silver STT now exists. Five of the six things I previously scored as missing are now specified:

| New / changed | What it unlocks |
|---|---|
| **`dwh_aa_fact_achievement_personal`** — champion type, date, host country, competing-countries count, **`competition_rank`**, participants count, olympic-profession flag, weight/discipline category, athlete gender + age category, score | Real medal/achievement counts by rank, gender, competition tier — 5 charts I had marked "no source" |
| **`dwh_aa_fact_achievement_group`** — same shape at group level, with `group_name`, `end_date`, `competition_rank` | Team achievements |
| **`dwh_aa_fact_trainers`** — coaches + instructors unified, with `role_desc` (מאמן / מדריך / מאמן לאומי), gender, branch, association, society, year | Athletes-per-coach ratio, coach gender split |
| **`dwh_aa_fact_office_roles_sport`** — official roles per association, **with gender** | Governance / women-in-leadership view (feeds the women's-sport dashboards too) |
| **`dwh_aa_fact_budget_pct`** — allocation budget by `area_name` (ייעוד תחום) and `measurement_for_area` (אמת מידה), with `percent` and `allocation_budget_amount` per `support_year` | The "support by purpose" donut **and** the attribution screen of the scoring engine |
| **`approved_amount` is now a Gold column** on the request fact (`mrr_aa_budgets`, via union) | Money is officially in the contract, not just in the ETL |
| **`area_name`** on the request fact + **`branch_area`** on `dim_branchs` | "ייעוד" exists as a dimension — my previous "cross-test only, unavailable" call is now wrong |
| **Multi-level threshold flags** on both facts: athlete / team / society / association / total, with the exact CASE logic per request type | A threshold-funnel screen becomes a real option (see §5.11) |
| `age` redefined as `assessment_year − birth_year` (was request year) | Age is as-of the assessment year — worth stating on any age visual |
| Silver `municipalities` carries much more than `dim_authority` exposes: `distance_from_tel_aviv_km`, `area_km2`, `population_growth_pct_yoy`, socioeconomic **index value + rank**, compactness cluster/index/rank, peripherality **index value + rank** | Finer periphery/equity analysis is a column-promotion away, not a new source |
| Silver `new_supporttesttypes` + `new_allocationbudgetstoareaandm` | Support tests exist as an entity with per-test budget allocation — the catalog tab is no longer flatly impossible |

**The caveat that governs all of it:** every sheet in both workbooks is marked **STT Status = In Progress**, and the **ETL Status cell is empty on all 12 Gold tables**. The contract is agreed; the pipeline is not confirmed built. So 🟢 items are planning-safe but not demo-safe until someone confirms the tables are loaded.

## TL;DR

- **Release 1 (2–3 weeks, tables already proven in production):** `הסתכלות גיאוגרפית` + `ביצועים ומגדר` (score-based) + `תמיכות` (rescoped) + `קישורים`.

But it moved from "impossible" to "one Gold column away": Silver has the test entity and its budget allocations; `dwh_aa_fact_budget_pct` just doesn't carry `support_test_type_code`.
- **Still empty against any data:** `SLA · תפעול`, `עמידות וחירום`, and the nonprofit-financials half of `גוף נתמך`.

## 2. The DWH contract as it now stands

### Gold facts

**`dwh_aa_fact_athlete`** — athlete × support request.
`athlete_code`, `athlete_id`, `request_type`, association / society / team / league keys and names, `athlete_gender`, `athlete_final_score`, `age` (= `assessment_year − birth_year`), `athlete_age_category`, `athlete_has_insurance`, `athlete_has_medical_check`, branch, authority, `support_request_year`, `support_request_code`, plus the threshold set: `is_pass_threshold_athlete`, `is_pass_threshold_team`, `is_pass_threshold_society`, `is_pass_threshold_association`, `is_pass_threshold_total_association`, `is_pass_threshold_total_society`, `is_budget_pass_final_threshold`.

**`dwh_aa_fact_support_request_sport`** — support request.
`support_request_code`, `request_type` (איגוד / אגודה / קבוצה / אישי / אליפות אירופה), `request_type_filter`, `request_name`, **`approved_amount`**, **`area_name`**, branch / league / authority / society / association / team keys, `male_cnt`, `female_cnt`, `male_score`, `female_score`, `achievement_score`, `male_achievement_score`, `female_achievement_score`, `professional_score`, `coach_association_score`, `branch_cost_score`, `women_promotion_score`, `excellent_center_score`, `is_pass_professional_condition`, `is_pass_admin_condition`, and the per-level threshold flags incl. `is_pass_threshold_total`, `support_request_year`.

**`dwh_aa_fact_achievement_personal`** — athlete achievement.
`champion_type`, `champion_date`, `host_country`, `competition_countries_cnt`, `competition_gender`, `competition_age_category`, `athlete_gender`, `athlete_age_category`, `competitor_team_size` (solo/pair/trio), `sport_weight_category`, `participants_cnt`, `is_olympic_profession_world`, `score`, athlete name (HE/EN), `athlete_support_request_code`, **`competition_rank`**, branch, `support_request_year`, `support_request_code`.

**`dwh_aa_fact_achievement_group`** — group achievement.
`group_branch_achievements_code`, `champion_type`, `end_date`, `competition_countries_cnt`, `gender`, `competition_age_category`, `score`, **`competition_rank`**, branch, `group_name`, year, request code.

**`dwh_aa_fact_trainers`** — coaches and instructors (union of `new_trainers` + `new_officials`).
`person_code`, `first_name`, `last_name`, `gender`, `role_desc`, branch, association, society, `support_request_year`.

**`dwh_aa_fact_office_roles_sport`** — official roles.
`official_code`, name, `official_gender`, `official_desc`, branch, association, `support_request_year`.

**`dwh_aa_fact_budget_pct`** — budget allocation.
`support_year`, `allocation_budget_amount`, `goal_type` (תחום / אמת מידה), `area_name`, `measurement_for_area`, `percent`.

**Also in production but absent from the STT:** `dwh_aa_fact_athlete_by_branch_society` (used by the production diagnostics) and the raw `mrr_aa_budgets`.

### Gold dimensions

| Dim | Fields that matter here |
|---|---|
| `dwh_aa_dim_authority` | `total_population`, `total_males/females`, ethnic split %, `lamas_district`, `crm_district`, `municipal_status`, **`socioeconomic_cluster`**, **`peripherality_cluster`**, `head_authority_name`, `key_authority` |
| `dwh_aa_dim_branchs` | `personal_or_group`, `branch_type` (מועדף / חשיבה / על / רגיל), `is_olympic_branch`, `is_special_needs_branch`, `is_sub_branch`, `sport_type` (incl. paralympic), `main_branch_name`, **`branch_area`** |
| `dwh_aa_dim_association` | `provider_num` (Merkava supplier no.), `main_branch_name/code` |
| `dwh_aa_dim_society` | `authority_code`; `authority_name` is annotated **"לא רלוונטי"** — take locality from the fact / `dim_authority` |
| `dwh_aa_dim_teams` | `team_achievement_score`, `team_number`, `society_id` |

### Silver layer (21 tables) — what's staged but not yet surfaced in Gold

- **`municipalities`** (LAMAS) — everything in `dim_authority` **plus** `distance_from_tel_aviv_km`, `area_km2`, `population_growth_pct_yoy`, `socioeconomic_index_value` + `socioeconomic_rank`, compactness cluster/index/rank, `peripherality_index_value` + `peripherality_rank`, `ingestion_timestamp`.
- **`new_supporttesttypes`** — `support_test`, `support_year`, `permission_system_code`, `test_type`, main scoring entity. The support tests as first-class entities.
- **`new_allocationbudgetstoareaandm`** — allocation per test: `support_test_type_code`, `support_year`, `goal_type`, `area_name`, `measurement_for_area`, `percent`, `allocation_budget_amount`, `budget_frame_name`, `budget_setting_type`. **Gold's `fact_budget_pct` drops `support_test_type_code`** — that single column is what separates "this test's purposes" from "the portfolio".
- **`new_ageforgroups`** — age-band definitions with gender, from/to age, and per-branch-type applicability flags.
- **`budget`** — the Excel-sourced approved amounts (`אקסל תקציב איגודים 25`), with `society_id` and `team_number` currently mapped to `null`. That is exactly the join-drop mechanism (B2) visible in the contract.

### The scope boundary

Gold is `dwh_aa_*` — associations and clubs. It does not carry the other support tests' outcomes, emergency tests, procurement/regulation channels (3א / רכש / תאגיד), facilities, or the ministry's own budget. Any ministry-wide number on the mockup remains illustrative.

### 5.7 `גוף נתמך · מנוע הניקוד`

**Scoring-engine half — ✅ / 🟢 now.** "Attribution — budget by test and criterion" is precisely `fact_budget_pct`: `goal_type` (תחום / אמת מידה), `area_name`, `measurement_for_area`, `percent`, `allocation_budget_amount`, joined to the request fact's per-criterion scores and `approved_amount`. Within associations & clubs this is a defensible screen as soon as the fact lands.

**Organization-profile half — 🟠 Release 2.** Income, employees, volunteers, members, status, classification, objectives from the **open nonprofit-registry API** (`data.gov.il`, CKAN, no credentials) — days-to-weeks of ETL. On-screen caveat: the dependency metric's numerator covers one test only, so it under-reports.

**⛔ Long:** GuideStar flags (proper management, §46, deficit year) need an account; multi-year revenue needs accumulated snapshots; expense breakdown is PDF-only.

### 5.8 `קטלוג התוכניות` — 🟡, and no longer hopeless
Silver now has the two tables a catalog needs: `new_supporttesttypes` (the tests, by year and system) and `new_allocationbudgetstoareaandm` (budget and % per test, per purpose, per criterion, with budget-frame metadata). Two gaps: Gold's `fact_budget_pct` drops `support_test_type_code` (B7), and it's unverified whether the CRM's test list covers all 17 tests in the mockup or only those administered in this system. Interim option stands: a hand-maintained, dated, owned reference table.

### 5.9 `SLA · תפעול` — ⛔ / candidate to drop
No source in the DWH, and the meeting already concluded the volume is too thin (≈6 inquiries a year). Connect the internal inquiry system, or remove the tab.

### 5.10 `עמידות וחירום` — ⛔ long
Four emergency tests plus shelter placement, which lives in the manually maintained facilities workbook. Nothing in the DWH.

### 5.11 New screen the STT now makes possible — threshold funnel
Both facts carry per-level threshold flags with documented logic: athlete → team → society → association → total, plus `is_budget_pass_final_threshold`, and the CASE rules differ by request type (`קבוצה רגילה`, `אליפות אירופה`, `איגוד`, `אישי`). That is a full drop-off funnel — how many applicants fail, at which level, in which branch — with zero new sourcing. It also answers the modelling question already explored in `אלטרנטיבות_מידול_תנאי_סף.html`. Worth pitching alongside R1.
