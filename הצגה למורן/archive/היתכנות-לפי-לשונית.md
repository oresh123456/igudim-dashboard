# Feasibility by tab — `מוקאפ-אסטרטגי-מורן.html`

**Date:** 20/08/2026 · **Scored against:** `STT_Aigudim_Agudut_Gold.xlsx` + `STT_Aigudim_Agudut_Silver.xlsx` (revision of 20/08/2026), **which are in production**.

**Scope of this assessment: the data warehouse only.** Nothing in this repo counts as evidence — not the mockups, not the Excel workbooks, not the boundary files, not the diagnostic SQL. A visual scores well here if and only if the fields it needs exist in the STT.

## Scoring

| Mark | Meaning |
|---|---|
| **מכוסה ב-DWH** | Every field the visual needs exists in the warehouse |
| **חלקי** | Some fields exist, some don't — or a rule/decision has to be supplied that isn't data |
| **לא ב-DWH** | The core measure is absent; it needs a source outside the warehouse |
| **עומק היסטוריה** | Schematically covered, but the visual is a trend — its usefulness depends on how many years are loaded, which the STT does not state |

## 2. What the warehouse contains

### Gold facts

| Fact | Grain and key fields |
|---|---|
| `fact_athlete` | Athlete × request. Gender, final score, `age`, age category, insurance, medical check, branch, authority, society, association, team, league, year, and the full threshold set (athlete / team / society / association / totals) |
| `fact_support_request_sport` | Request. **`approved_amount`**, **`area_name`**, request type (איגוד / אגודה / קבוצה / אישי / אליפות אירופה), male & female counts and scores, achievement / professional / coach / branch-cost / women-promotion / excellence-centre scores, all threshold flags, year |
| `fact_achievement_personal` | Athlete achievement. **`competition_rank`**, champion type, `champion_date`, host country, competing-countries count, participants count, olympic-profession flag, discipline/weight category, competition and athlete gender, age category, score |
| `fact_achievement_group` | Group achievement. Rank, gender, age category, score, group name, `end_date` |
| `fact_trainers` | Coaches and instructors. `role_desc` (מאמן / מדריך / מאמן לאומי), gender, branch, association, society, year |
| `fact_office_roles_sport` | Official roles. Gender, role description, association, branch, year |
| `fact_budget_pct` | Allocation. `goal_type` (תחום / אמת מידה), `area_name`, `measurement_for_area`, `percent`, `allocation_budget_amount`, `support_year` |

### Gold dimensions

`dim_authority` — population, male/female totals, ethnic splits, LAMAS and CRM district, municipal status, **socioeconomic cluster**, **peripherality cluster**.
`dim_branchs` — individual vs team, branch type (מועדף / חשיבה / על / רגיל), olympic, special-needs, sub-branch, sport type incl. paralympic, **`branch_area`**.
`dim_association` — supplier number, main branch. `dim_society` — authority code (`authority_name` marked "לא רלוונטי"). `dim_teams` — achievement score.

### Silver — in production, but not surfaced in Gold

- `municipalities` — the continuous socioeconomic and peripherality **index values and ranks**, distance from Tel Aviv, area, compactness, population growth. Richer than what `dim_authority` exposes.
- `new_supporttesttypes` — the support tests as entities, by year and administering system.
- `new_allocationbudgetstoareaandm` — allocation per test, carrying **`support_test_type_code`**, which `fact_budget_pct` drops.
- `new_ageforgroups` — age-band definitions with gender and per-branch-type applicability.
- `budget` — approved amounts, with `society_id` and `team_number` mapped to `null`.

### The scope boundary

Gold is `dwh_aa_*` — **one support test, associations and clubs**. Other tests' outcomes, emergency tests, procurement channels, facilities and the ministry's own budget are not in it. The mockup's ₪148.1M / 476 bodies / 17 tests framing is illustrative.

## 3. Open items

| # | Item | Why it matters |
|---|---|---|
| **B1** | How many years of `support_request_year` are loaded | A *data-content* question the STT cannot answer. Gates 7 trend visuals — all schematically covered |
| **B2** | The Silver `budget` sheet maps `society_id` and `team_number` to `null` | The join key can't match on those fields, so amounts drop. Visible in the contract itself. Now a **production** issue |
| **B3** | Scope labelling | Any ministry-wide framing on a live dashboard has no warehouse behind it |
| **B5** | Association-level (`איגוד`) requests are national | `authority_id` is meaningless for them; the geographic view is a *clubs* view unless a rule allocates them |
| **B7** | `fact_budget_pct` omits `support_test_type_code` | The column exists in Silver. Exposing it converts the catalog tab from partial to covered |
| **B8** | Type declarations in `fact_trainers` / `fact_office_roles_sport` | `first_name` and `branch_name` as `Int64`, `branch_id` and `association_id` as `string`. Verify against the live tables — either the STT is wrong or the tables are |

## 4. Build order

**Wave 1 — the covered tabs.** ביצועים ומגדר (83%) · הסתכלות גיאוגרפית (75%) · IMPACT (75%) · קישורים. Ship the covered visuals; drop or substitute the handful that aren't.
**Wave 2 — one decision each.** תמיכות (50%) once B3 is decided and B1 is known · מנופי מדיניות (33%) once the premium rules are encoded · קטלוג once B7 is done.

## 7. Implementation notes

- Athlete count beside budget: join on `support_request_code` at athlete grain, count athletes distinctly, and divide `approved_amount` by the request's row count so it is counted once.
- Achievement facts attach on `support_request_code`; the personal one also carries `athlete_support_request_code`, so either grain works.
- Locality joins go through the fact or `dim_authority`, never `dim_society.authority_name`.
- Every covered visual maps to a native QuickSight type: KPI, bar, stacked/clustered bar, line, donut, scatter, table with data bars, filled map.
