1 The decision — and why the other paths dropped ▸

Requiring viewers to be authenticated collapses the option set fast:

PathStatusWhy
1-click publicOutExposes data with no login — fails the "registered" rule.
Anonymous (API)OutNo sign-in by design; also needs coding + session capacity.
Registered-user (API)DeferredOnly worth it for seamless SSO in a custom app, or to embed the Q bar. Needs a backend.
1-click registered-userChosenNo code, cheapest for a known user set, viewers sign in.

You can still upgrade to the API path later without redoing the dashboards — same content, different delivery.

2 What Path 2 entails — prerequisites ▸
Edition
Enterprise edition primary required.
Viewers
Each viewer is a registered reader in your QuickSight account, granted access to the dashboard.
Sign-in
Viewers are prompted to log in once; with SSO they aren't prompted again primary.
Browser
BroadcastChannel / IndexedDB / LocalStorage support, and "block all cookies" turned off primary.
Coding
None — a static embed code, no embedding API call.
3 The 4 steps ▸

  1. Grant dashboard access

    Grant the users/groups access primary (or everyone in the account). Visual permissions inherit from the dashboard.

  2. Allow-list the page's domain

    In QuickSight, make sure the embedding domain is allow-listed primary.

  3. Copy the embed code

    Open the dashboard → Share → Share dashboard → Copy embed code primary. (Per-visual: on-visual menu → Embed visual → Copy code.)

  4. Paste into your page's HTML

    Drop the iframe into any internal page — including a Google Sites embed widget or a SharePoint Embed web part. Several iframes on one page = your composite dashboard.

embed.html — dashboard iframe
<!-- static embed code copied from QuickSight — no API call -->
<iframe
  width="960" height="720"
  src="https://{{quicksightdomain}}/sn/embed/share/accounts/{{accountid}}/dashboards/{{dashboardid}}?directory_alias=account_directory_alias">
</iframe>

A defined internal user list → per-user ($3/reader/mo) is the simplest and almost certainly cheapest. No session accounting. Dashboard authors are billed separately at $24 / author / month primary.

5 What you give up (vs the API path) ▸
  • Content: dashboards + visuals only — no Q search bar via 1-click.
  • Same static iframe for everyone — personalization comes only from each viewer's login + row-level security in the dashboard, not from your app passing context.
  • Provisioning: every viewer must exist as a QuickSight reader in your account (inherent to "registered").
When to step up to the API path

Choose programmatic registered-user embedding only if you need invisible SSO in a custom app (no QuickSight login screen at all), the Q natural-language bar, or app-driven per-user context. It costs a few days of backend work.

6 Recommendation & next steps ▸
Recommended

Go with 1-click registered-user embedding on a single internal page. Bill viewers per-user ($3/mo). Wire SSO so the login is invisible — that's the one upgrade that turns this from "good" to "seamless".
